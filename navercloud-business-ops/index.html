01 / PARTNER POLICY & COST RECOVERY

물류 사고 접수 기준을 다시 정의했습니다.

PROBLEM

파손 사고 접수에 사진 3종, 재포장, 실물 보관·회수까지 요구돼 식품 누수나 유리 파손처럼 보관이 어려운 건은 고객이 절차를 포기하면 배상 접수도 중단됐습니다.

JUDGMENT

모든 사고에 같은 증빙을 요구하는 것이 문제라고 봤습니다. 사고 확인에 반드시 필요한 증빙과 고객에게 불필요하게 전가되는 절차를 나눴습니다.

ACTION

파트너 사업팀과 ‘실물 회수 생략·증빙 간소화’ 방향을 도출했고, 내품 사진이 없을 때의 대체 증빙처럼 확정되지 않은 세부 기준은 후속 논의로 분리했습니다.

RESULT

비교 월 기준 배상 회수액이 507,000원에서 7,449,621원으로 약 14.7배 확대됐습니다.

NAVER Cloud 연결 · 파트너 운영 조건을 현장 기준으로 재설계하고, 예외 범위와 비용 회수 구조를 함께 개선한 경험입니다.

02 / COST EFFICIENCY

운영 변화에 맞춰 고정비 구조를 다시 계산했습니다.

PROBLEM

게시판 중심 운영으로 전화 수요가 크게 줄었지만 기존 6개 회선이 그대로 유지돼 월 528,000원의 고정비가 발생하고 있었습니다.

JUDGMENT

과거 사용량이 아니라 현재 실제 동시통화 수요를 기준으로 필요한 용량을 다시 봐야 한다고 판단했습니다.

ACTION

운영 패턴과 동시통화 필요량을 확인해 1~2회선이면 운영 가능하다고 산정하고 업체와 축소 조건을 협의했습니다.

RESULT

6회선에서 2회선으로 조정해 월 비용을 528,000원에서 176,000원으로 낮췄고, 월 고정비를 66.7% 적정화했습니다.

NAVER Cloud 연결 · 정기비용을 단순 집행하지 않고 실제 사용량과 운영 구조를 함께 보며 비용 조건을 재설계했습니다.

03 / PROCESS & AUTOMATION

1,928건의 대량 예외를 우선순위와 자동화로 다시 설계했습니다.

PROBLEM

물류 운영사 전환 직후 재배송 1,151건과 취소 777건이 동시에 쌓였습니다. 같은 순서로 처리하면 고객 약속, 재고, 처리 마감이 함께 밀리는 상황이었습니다.

JUDGMENT

모든 업무를 자동화하기보다 고객 영향과 마감 리스크를 먼저 나누고, 사람이 판단할 필요가 없는 반복 입력만 제거하는 것이 안전하다고 봤습니다.

ACTION

재배송을 우선 처리하도록 작업 순서를 바꾸고 관리자 화면의 정형 입력을 Chrome Extension으로 자동화했습니다. 주말 선처리 후 잔여 업무량을 다시 계산했습니다.

RESULT

반복 등록 동선을 7단계에서 1단계로 줄였고, 남은 처리량을 기준으로 지원 인력을 3명에서 2명으로 재산정했습니다.

04 / OPERATIONS MONITORING

자금집행을 ‘원본 확인’에서 ‘우선순위 확인’으로 바꿨습니다.

PROBLEM

지급완료, 당일 필수, 일반, 누적 미집행, 보류 건이 하나의 목록에 섞여 있어 매번 원본을 다시 읽어야 했고 납기나 서비스 중단 위험이 있는 항목을 놓치기 쉬웠습니다.

JUDGMENT

금액 전체를 다시 읽는 것보다 ‘오늘 반드시 확인해야 하는 항목’과 그 이유가 먼저 보여야 운영 의사결정이 빨라진다고 봤습니다.

ACTION

지급 상태·중요도·납기·운영 영향 기준으로 목록을 자동 분류하고 법정 납부기한이나 서비스 제한 가능성이 있는 항목을 별도로 표시했습니다.

RESULT

매일 오전 9시에 당일 우선 확인 대상을 한 번에 볼 수 있는 요약 구조를 만들었습니다.

NAVER Cloud 연결 · 과제·비용·리스크를 상태와 우선순위로 구조화해 반복적인 확인 업무를 의사결정 중심의 모니터링으로 바꾼 경험입니다.

RESULT

400여 제휴사 정책을 같은 구조에서 확인할 수 있게 하면서 담당자별 판단 편차를 줄였습니다.

NAVER Cloud 연결 · 다수 파트너의 서로 다른 조건을 공통 데이터 구조와 운영 기준으로 정리해 확장 가능한 파트너 운영 체계를 만든 경험입니다.
