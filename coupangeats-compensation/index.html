01 / COMPENSATION POLICY · 약 14.7배

‘회수 없이는 보상 불가’였던 사고 기준을 파트너 자체 약관을 근거로 다시 협의했습니다.

Problem

파손 사고 접수에 외부박스·운송장·내품 사진과 실물 회수가 일률적으로 요구돼, 고객이 위험한 파손 상품을 보관하거나 추가 증빙을 포기하면 배상 접수도 중단될 수 있었습니다.

Judgment

고객 불편을 이유로 개별 예외를 요청하는 방식만으로는 파트너의 ‘회수 없이는 보상 불가’ 원칙을 바꾸기 어려웠습니다. 파트너가 스스로 정한 통보·사고 조치 의무가 실제 운영에서 어떻게 이행되는지로 논점을 바꿨습니다.

Action

택배 표준약관의 재포장 시 송화인 통보 의무와 사고 발생 시 조치 의무를 근거로 재협의했습니다. 이후 실제 운영에서는 택배사 전산에 사고 이력이 있는 건은 추가 사진·실물 회수 없이 주문내역서로 접수하고, 미등록 건은 사진 3종 대신 겉박스 파손 사진 1장으로 사고를 확인하도록 증빙 기준을 나눴습니다.

Result

반복 증빙과 위험 상품 보관 부담을 줄이고 기존 요건 때문에 중단되던 사고를 배상으로 연결했습니다. 비교 월 배상 회수액은 50만 원대에서 약 744만 원으로 확대됐습니다.

02 / SETTLEMENT · COST · 계약 기준

3PL 귀책 피해와 회사 선처리 비용을 계약 기준으로 묶어 정산 자료로 관리했습니다.

Problem

출고 누락·포장 불량·파손 등 3PL 귀책 피해가 발생하면 회사가 먼저 처리한 환불·재배송·CS 보상 비용을 어떤 근거로 익월 물류비에 반영할지 정리가 필요했습니다.

Action

물류 계약서 원문을 기준으로 피해 유형·회사 선처리 비용·차감 예정액·조정 가능 항목을 월별로 정리했습니다. 파트너가 제시한 확정액 중 본사 기준과 맞지 않거나 추가 확인이 필요한 건은 별도로 표시했습니다.

Result

실제 피해와 계약 조항을 연결한 정산 협의 자료를 만들고, 확정액을 그대로 수용하지 않고 재검토할 수 있는 구조로 관리했습니다.

Learning

정산 정확도는 금액 자체보다 어떤 피해가 어떤 근거로 반영됐는지 추적 가능하게 만드는 데서 시작됐습니다.

03 / AUTOMATION · OPERATIONS · 1,928건

대량 예외 1,928건을 우선순위로 나누고 반복 등록을 자동화한 뒤 필요한 인력까지 다시 계산했습니다.

Problem

외부 물류 운영사 전환 직후 재배송 1,151건과 취소 777건이 동시에 발생했고, 반복 입력까지 겹쳐 처리 지연 위험이 컸습니다.

Action

고객 약속·재고·후속 기한을 기준으로 재배송을 먼저 처리하고, 관리자 화면의 정형 입력은 Chrome Extension으로 자동화했습니다. 귀책·금액·최종 처리처럼 확인이 필요한 값은 사람이 검수하도록 남겼습니다.

Result

총 1,928건을 유형과 처리 시점으로 나눠 운영했고 반복 등록 동선을 7단계에서 1단계로 줄였습니다. 자동화 적용 후 필요한 지원 인력도 3명에서 2명으로 다시 산정했습니다.

Learning

자동화는 입력을 대신하는 데서 끝나는 게 아니라, 사람이 책임져야 할 판단 구간을 분명하게 남길 때 안정적으로 작동했습니다.

Problem
