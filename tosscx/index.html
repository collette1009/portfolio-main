CASE 04
CASE 01 · EVENT / ACCURACY

프로모션 VOC 173건 → 142건(82.1%) ‘문구 미인지’ → 조건·처리 기준 분리

반복 문의를 상담자의 설명 문제로 보지 않고, 혜택 조건이 고객 행동 시점에서 어떻게 인지되는지 데이터로 다시 봤습니다.

PROBLEM

1+1 문의가 반복됐지만, 고객이 실제로 어느 조건에서 오인하는지 근거가 없었습니다.

ACTION

VOC 173건을 전수 분류하고 원인 유형·고객 행동 시점·채널을 함께 확인했습니다.

RESULT

원인 유형 기준 142건(82.1%)이 ‘문구 미인지’로 확인돼 초회 예외와 재인입 종결 기준을 분리했습니다.

LEARNING

혜택 운영은 문구 하나가 아니라 적용 조건·시점·예외를 같은 기준으로 관리해야 정확도가 올라갑니다.

실제 운영 시트의 개인정보 없는 집계 영역: 문구 미인지 142 · 정책 기준 혼동 12 · 홀수 수량 알림 부재 19 · 합계 173
Source · 업로드된 ‘CS 운영 근무 스케줄.xlsx’의 ‘1+1 미적용 VOC’ 탭 집계값을 기반으로 요약 영역만 재현했습니다. 고객명·주문번호 등 개인정보는 사용하지 않았습니다.
CASE 02 · PARTNER OPERATIONS

400여 제휴사 정책 → 공통 속성 정의 → 같은 순서로 판단

파트너마다 다른 정책을 개별 암기로 처리하지 않고, 공통 필드와 예외·변경 이력으로 관리했습니다.

PROBLEM

골프장마다 정책 위치·표현·상세 수준이 달라 확인 순서와 판단이 담당자마다 달랐습니다.

ACTION

400여 곳을 전수 확인해 공통 속성을 만들고 불명확한 내용은 제휴사에 직접 확인했습니다.

RESULT

제휴사와 관계없이 같은 순서로 정보를 찾고 판단할 수 있는 기준을 만들었습니다.

LEARNING

파트너 수가 늘수록 공통 필드·예외·변경 이력 관리가 운영 정확도와 러닝커브를 좌우합니다.

CASE 03 · ADMIN / CRM

고객 의도를 자유 텍스트에서 선택값으로 → CRM 판단 구조 개선

고객의 환불/교환 의도가 후속 담당자에게 바로 전달되지 않는 문제를 ‘입력 구조’ 문제로 바꿔 해결했습니다.

PROBLEM

고객 의도가 상담 내용에 묻혀 후속 담당자가 다시 읽거나 고객에게 재확인해야 했습니다.

ACTION

고객이 해결방법을 선택하고 그 값이 CRM에서 바로 보이는 흐름을 유관부서에 제안했습니다.

RESULT

후속 담당자가 고객 의도를 바로 확인할 수 있는 구조로 바뀌어 판단 기준이 명확해졌습니다.

LEARNING

어드민 개선은 화면을 늘리는 것이 아니라 다음 담당자의 ‘재해석 비용’을 줄이는 일입니다.

유관부서에 ‘해결방법’ 선택 필드 신설과 CRM 노출을 제안한 실제 협업 화면
선택값이 후속 담당자에게 이어지도록 정리한 CRM Before → After
CASE 04 · AUTOMATION / OPERATIONS

1,928건 대량 예외 → 우선순위 분리 + 반복 등록 7→1단계

업무량이 커질수록 ‘무엇을 먼저 할지’와 ‘어디까지 자동화할지’를 따로 설계했습니다.

PROBLEM

물류 전환기 대량 예외와 반복 입력이 동시에 쌓여 고객 약속·재고·후속 기한을 함께 관리해야 했습니다.

ACTION

재배송 1,151건과 취소 대상 777건을 우선순위로 나누고 반복값/판단값을 분리해 Extension을 구현했습니다.

RESULT

재배송을 우선 처리하고 반복 등록 동선을 7→1단계로 단순화해 대량 처리에도 같은 도구를 사용했습니다.

LEARNING

좋은 자동화는 판단을 없애는 것이 아니라 정형 입력은 줄이고 책임이 필요한 확인은 남기는 것입니다.

반품사유·귀책·상세사유 등 반복 항목을 자동 입력하도록 만든 실제 관리자 화면
CASE 05 · PRODUCT IMPROVEMENT

배송 제약 동일 문의 5건 → 원인 상품 가시화 → 당일 반영 후 0건

고객에게는 ‘품절/오류’처럼 보였지만 실제 원인은 특정 상품의 배송 제약이 화면에 보이지 않는 것이었습니다.

PROBLEM

운영 첫날 동일 문의 5건이 누적됐고, 실제 품절이 아닌데도 고객이 원인 상품과 제한 사유를 알 수 없었습니다.

ACTION

재고·배송 조건을 검증하고 원인 상품과 배송 가능 조건을 같은 화면에 보여주는 노출 조건/문구를 정리했습니다.

RESULT

개발팀이 당일 반영했고 이후 동일 문의는 0건으로 확인됐습니다.

LEARNING

고객이 판단하는 시점에 필요한 조건이 보이면 안내를 늘리지 않고도 문의 자체를 줄일 수 있습니다.

원인과 시스템 구분 가능 여부, 최소 개선안과 안내 문구를 개발 담당자와 논의한 과정
원인 상품과 배송 제약을 장바구니 단계에서 바로 확인하도록 반영한 화면
