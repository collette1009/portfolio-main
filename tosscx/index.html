01 · 프로모션 운영

Problem

1+1 혜택이 적용되지 않았다는 문의가 반복됐지만, 고객이 실제로 어느 조건에서 오인하는지 근거가 없었습니다.

Action

VOC 173건을 전수 분류하고 원인 유형·고객 행동 시점·채널을 함께 확인했습니다. 단순 문의량이 아니라 고객이 조건을 놓친 지점을 보려 했습니다.

Result

원인 유형 기준 142건(82.1%)이 ‘문구 미인지’로 확인됐고, 초회 예외 처리와 재인입 시 정책 안내·종결 기준을 분리했습니다.

Learning

혜택 운영에서는 문구 자체보다 적용 조건·노출 시점·예외를 같은 기준으로 관리해야 고객 오인을 줄일 수 있었습니다.

Problem

Action

Result

03 · CRM 개선

고객 의도를 자유 텍스트에서 선택값으로 바꿔 후속 판단을 단순화

Problem

환불·교환 등 고객이 원하는 해결방법이 상담 내용에 묻혀 후속 담당자가 다시 읽고 판단하거나 고객에게 재확인하는 일이 생겼습니다.

Action

고객이 ‘원하는 해결방법’을 먼저 선택하고 그 값이 CRM 솔루션 필드에서 바로 보이도록 입력 구조 개선안을 유관부서에 제안했습니다.

Result

후속 담당자가 고객 의도를 구조화된 값으로 바로 확인할 수 있어 재확인 왕복과 담당자별 해석 차이를 줄였습니다.

Learning

운영 효율은 답변을 더 잘 쓰는 것보다 다음 사람이 다시 해석해야 하는 정보를 줄일 때 더 크게 좋아졌습니다.

04 · 운영 자동화

1,928건 대량 예외를 우선순위로 나누고 반복 입력 동선을 7→1단계로 축소

Problem

3PL 전환 과정에서 재배송 1,151건과 취소 대상 777건이 동시에 발생했고, 고객 약속일·재고·후속 처리 기한 때문에 모든 건을 같은 순서로 처리할 수 없었습니다.

Action

재배송과 취소를 고객 영향과 처리 시점으로 먼저 분리하고, 반복적으로 입력하는 정형값만 Chrome Extension으로 자동화했습니다. 귀책·금액·최종 등록처럼 책임이 필요한 값은 사람이 확인하도록 남겼습니다.

Result

재배송 1,151건을 우선 처리하고 반복 등록 동선을 7→1단계로 줄였습니다. 남은 업무량을 다시 산정해 필요한 지원 인력도 3명에서 2명으로 조정했습니다.

Learning

좋은 자동화는 판단을 없애는 것이 아니라 사람이 판단할 구간과 기계가 반복할 구간을 분명하게 나누는 것이었습니다.

05 · 제품 개선

배송 제약 동일 문의 5건 → 원인 상품 가시화 → 당일 반영 후 0건

Problem

배송 제약 상품이 장바구니에 섞이면 고객에게는 품절이나 시스템 오류처럼 보였습니다. 운영 첫날 같은 문의가 5건 누적됐습니다.

Action

장바구니 조합과 재고·배송 조건을 확인한 뒤, 원인 상품 옆에 제한 사유를 보여주는 최소 개선안을 개발 담당자에게 제안했습니다. 시스템에서 구분 가능한 조건과 안내 문구까지 함께 정리했습니다.

Result

개발팀이 당일 반영했고 이후 동일 문의는 추가로 들어오지 않았습니다. 유사한 배송 제약 상품에도 같은 방식으로 확장했습니다.

Learning

고객이 판단하는 바로 그 시점에 필요한 조건을 보여주면 안내 문구를 늘리지 않고도 문의 자체를 줄일 수 있었습니다.
