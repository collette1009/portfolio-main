CASE 01 · EVENT / ACCURACY

프로모션 VOC 173건 → 142건(82.1%) ‘문구 미인지’ → 조건·처리 기준 분리

PROBLEM

1+1 프로모션인데 혜택이 적용되지 않았다는 문의가 반복됐고, 단순 불만이 아니라 고객이 어떤 조건을 놓치는지 확인할 필요가 있었습니다.

ACTION

VOC 173건을 전수 분류해 원인을 ‘문구 미인지’, ‘정책 기준 혼동’, ‘홀수 수량 알림 부재’로 나누고 고객 행동 시점까지 함께 봤습니다.

RESULT

142건(82.1%)이 문구 미인지로 확인돼 단순 상담 스크립트 문제가 아니라 혜택 조건 인지 구조의 문제임을 수치로 확인했습니다.

LEARNING

혜택 운영은 문구 자체보다 고객이 조건을 인지하는 위치·시점·예외를 함께 관리해야 한다는 기준을 만들었습니다.

CASE 02 · PARTNER OPERATIONS

400여 개 제휴사별 상이한 정책 → 공통 속성으로 구조화 → 상담·변경 기준 표준화

PROBLEM

제휴 골프장마다 예약·취소·위약·동반자 기준과 안내 순서가 달라 같은 유형의 문의도 담당자마다 확인 방식이 달랐습니다.

ACTION

400여 개 제휴사 정보를 전수 정리하고 공통 속성을 뽑아 같은 순서로 확인할 수 있게 재구성했습니다. 애매한 기준은 제휴사에 직접 확인했습니다.

RESULT

제휴사별 정보를 하나의 구조로 읽을 수 있게 해 상담·예외 판단·변경 공유 기준을 통일했습니다.

LEARNING

파트너가 많을수록 개별 내용을 외우는 것이 아니라 공통 필드와 예외·변경 이력을 관리하는 구조가 중요합니다.

CASE 03 · ADMIN / CRM

자유 텍스트 고객 의도 → 선택값 → CRM 필드로 연결해 후속 운영의 해석 차이 축소

PROBLEM

환불·교환 의도가 자유 텍스트에 섞여 있어 후속 담당자가 다시 읽고 판단하거나 고객에게 재확인하는 왕복이 발생했습니다.

ACTION

‘원하는 해결방법’을 선택형 값으로 받고 CRM 솔루션 필드까지 연결되도록 구조를 제안해 유관부서와 반영했습니다.

RESULT

후속 담당자가 고객 의도를 구조화된 값으로 바로 확인할 수 있어 재확인과 해석 편차를 줄였습니다.

LEARNING

운영 효율은 상담 문구보다 입력 구조를 바꿀 때 더 크게 개선되는 경우가 있습니다.

CASE 04 · AUTOMATION

대량 예외 1,928건을 우선순위로 분리하고 반복 입력 동선을 7→1단계로 축소

PROBLEM

3PL 전환 과정에서 재배송 1,151건과 취소 777건이 동시에 발생했고, 재배송은 고객 약속일·재고 때문에 먼저 처리해야 했습니다.

ACTION

재배송·취소를 고객 영향과 처리 시점으로 분리하고, Chrome Extension으로 반복 관리자 입력을 자동화했습니다.

RESULT

정형 입력 동선을 7→1단계로 줄여 우선 처리 건을 빠르게 등록하고, 잔여 업무를 재산정해 지원 인력도 3→2명으로 조정했습니다.

LEARNING

자동화는 판단을 없애는 것이 아니라 사람이 봐야 할 귀책·금액·최종 등록은 남기고 반복 입력만 줄이는 방식이 안전했습니다.

→

→
우선순위 처리
→
반복 입력 자동화
Chrome Extension 적용 관리자 화면 · 정형 입력 구간 자동화
CASE 05 · PRODUCT IMPROVEMENT

운영 첫날 동일 문의 5건 → 원인 상품·배송 제약을 고객 화면에 노출 → 추가 인입 0건

PROBLEM

배송 제약 상품이 장바구니에 섞이면 고객은 품절이나 시스템 오류로 오인했고, 운영 첫날 같은 문의가 5건 누적됐습니다.

ACTION

장바구니 조합과 배송 조건을 확인한 뒤, 원인 상품 옆에 제약 사유를 노출하는 최소 개선안을 개발 담당자에게 제안했습니다.

RESULT

당일 반영 후 동일 문의가 추가로 들어오지 않았고, 유사 제약 상품에도 같은 방식으로 확장했습니다.

LEARNING

CS 오류를 빠르게 줄이려면 고객이 잘못 이해한 지점과 시스템이 이미 알고 있는 조건을 연결하는 것이 효과적입니다.

문제 재현 → 구분 가능 여부 확인 → 최소 개선안 제안
실제 장바구니 반영 · 원인 상품별 배송 제약 안내
